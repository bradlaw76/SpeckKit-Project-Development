# Implementation Plan: SpeckKit Compliance Dashboard

**Branch**: `001-compliance-dashboard` | **Date**: 2026-02-17 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-compliance-dashboard/spec.md`

## Summary

Build a single-page web application that connects to the SpeckKit System Manifest Registry via the GitHub API, audits governed repositories against their declared SpeckKit profiles, computes compliance scores, and presents results in a filterable dashboard. The app also supports discovering ungoverned repos, scaffolding missing files, and browsing standards catalogs. Built with React + Vite + TypeScript, deployed as a static site (GitHub Pages compatible).

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Primary Dependencies**: React 19, Vite 6, React Router (HashRouter)
**Storage**: Browser sessionStorage for audit cache; browser localStorage for auth tokens. No server-side storage.
**Testing**: Vite/Vitest (unit), manual browser testing (integration)
**Target Platform**: Modern web browsers (Chrome, Edge, Firefox, Safari). Static site deployed to GitHub Pages.
**Project Type**: Single-page web application (frontend only — no backend server)
**Performance Goals**: Dashboard renders in <3s on first load; auditing 10 projects completes in <10s with token.
**Constraints**: GitHub API rate limits (5000 req/hr authenticated, 60/hr unauthenticated); No server — all logic runs client-side; Private repos require PAT.
**Scale/Scope**: Supports up to 500 repos; 2-50 governed projects typical; single-user tool.

## Key Design Decisions

1. **GitHub API Contents endpoint** over raw.githubusercontent.com — works for both public and private repos when authenticated.
2. **SessionStorage cache with TTL** — avoids redundant API calls while ensuring data freshness.
3. **HashRouter** — enables GitHub Pages deployment without server-side routing.
4. **Batch auditing (3 concurrent)** — respects GitHub rate limits while providing reasonable speed.
5. **Template-based scaffolding** — pushes files via GitHub Contents API `PUT` with base64-encoded content.
